Multi Sync market configuration implementation report
Date: 7 October 2026

Outcome
Additional Market feeds can dynamically follow Primary Configuration or use their own saved configuration. Creation and editing now use dedicated Polaris pages. All XML continues through the existing feed generator.

Database and deployment
Both frontend and backend Prisma XmlLink models add:
- customConfigurationEnabled: nullable Boolean with default false.
- customConfiguration: nullable JSON containing only allowed market fields.
- marketConfigurationRevision: nullable Int with default 0 for concurrent-edit protection.
Missing/null mode is interpreted as OFF; missing/null revision is 0. There is no data backfill or migration, no new index, and no automatic generation. Optional MongoDB scalar fields require regenerated Prisma clients, not a destructive schema/data migration. No database push or production data operation was run. Deploy backend and frontend with their regenerated clients and matching local catalog-rules package exports. The dashboard schema does not need these fields because dashboard operations do not write market configuration.

Backward compatibility and identity
Old feeds resolve to the original Primary rules without requiring a resave. No existing records are recreated. Public URL/token, GCS object naming/directory functions, Shopify Market, market country, language, XML item ID Country Code, pricing/localization, billing, metering, allowances, and schedules retain their existing behavior. The Shopify market country and the separate idCountryCode used for g:id remain distinct. Legacy missing ID Country Codes continue using the existing fallback/freeze behavior.

Global-only settings
Alerts email; Color option mapping (including legacy/plural mappings); Size option mapping; Gender Rules and default Gender; Age Rules and default Age Group. Rule versions and bookkeeping are never copied into market JSON. Custom markets always receive current Primary global rules/mappings at execution.

Exact market-overridable fields discovered in the current codebase (15)
- Product inclusion: productSubmissionMode, includedCollectionIds.
- Collection exclusions: excludedCollections (stable IDs and display titles).
- Product-title exclusions: excludedTitleTerms.
- XML title cleanup: excludedTitleAttributes.
- Tag exclusions: excludedProductTags.
- Google options: showSalePriceInGoogleFeed, useProductImageAsMainImage, includeShippingWeightInGoogleFeed, excludeOutOfStockItems.
- Inventory: ignoreShopifyInventoryInGoogleFeed, inventorySourceMode, selectedInventoryLocationIds.
- URLs: disableUtmParameters, checkoutLinkMode.
The currency-parameter toggle disablePrimaryCurrencyParameter is intrinsically Primary-only: existing Additional URLs always retain currency for localized pricing. It is hidden and rejected as a market override. productTypes are Diagnostics suggestions, not feed configuration; they stay on Primary. Country Code is edited as feed identity, not custom configuration. The current Configuration does not offer separate title/description source, additional-image enablement, or variant submission controls; no new duplicate settings were invented. Existing image, pricing, custom-label, variant, transformation and serialization logic is reused unchanged.

Resolution architecture
The mirrored @multi-sync/catalog-rules/market-configuration subpath centralizes the explicit allowlist, logical sections, JSON validation, picking, effective resolution, and Primary-change impact comparison. Primary feeds return Primary rules. Additional OFF returns current Primary rules and ignores all retained JSON. Additional ON overlays only allowed saved fields onto current Primary rules. Global/stale/unknown override keys can never override Primary. Missing newly classified fields safely fall back to Primary until explicitly initialized/saved. New fields require a deliberate classification in this allowlist; frontend omission is not the business boundary.

Routing and setup
/app/market-feed/new: Market/country, available language, XML ID Country Code, Create feed.
/app/market-feed/configure: selected context, Customize configuration switch (OFF by default), optional custom editor, Generate feed.
/app/market-feed/:feedId: existing identity/context, editable Country Code, mode/custom settings, Save.
/app hides App Bridge navigation on these routes; standalone pages do not mount DashboardTabs. The top-left Polaris breadcrumb link contains a back arrow returning to /app/feeds. The editor includes retryable load feedback.
Create feed only navigates. No draft record, XML upload, successful status, queue job, or billing event is created; abandoned setup leaves nothing to clean up. Available combinations/languages are revalidated on step 2 and final generation. Final generation saves mode/allowed values atomically with a new XmlLink, then uses the existing store slot, billing eligibility, unique combination index and BullMQ enqueue. It polls the saved feed and returns to Feeds only on COMPLETED. Errors stay on the page, FAILED is retryable, and a ref guard/loading state prevents double submission. Existing paid usage consent and legacy subscription renewal UI remain explicit.

Editing and switches
Existing Market/country/language remain immutable, matching the previous editor. Country Code remains normalized and validated; Save never generates XML. Table switches exist only on Additional rows. They wait for the server, are disabled during the request, reject rapid repeats, restore saved state on failure, and show Polaris feedback. Initial ON copies only current Primary overridable values. Previously saved values are retained while OFF and restored on later ON; they are completely ignored while OFF. Missing newly classified fields are initialized from current Primary. Optimistic revision checks and conditional updates prevent a stale editor or concurrent queue/claim from overwriting settings. The legacy Country Code API also advances this revision.

Copy from Primary
Eight actions copy logical sections: inclusion, collection exclusions, title exclusions, title cleanup, tags, Google options, inventory, and URLs. Each reads current Primary on click, clones only that section, keeps Custom ON, and leaves other custom fields untouched. Copies are form edits committed by Save or Generate; later Primary changes do not mutate them. No Copy action appears on the main Configuration page. The optional Copy all action was omitted to keep the page compact.

Refresh required
Mode changes, effective custom settings changes and Country Code changes mark only the edited Additional feed. Saving an unchanged effective configuration does not newly mark it. No switch/save action queues generation or modifies published XML. Primary saves compare each published feed's before/after effective settings: Primary and inherited markets are marked for applicable changed fields, custom markets are marked only when their effective settings changed. Color/Size changes reach both modes; existing Gender/Age save/worker invalidation remains global. Alerts email and Diagnostics-only Product Types do not change XML. Primary-only country/currency options do not invalidate an Additional feed whose XML behavior is unchanged.

Workers and unchanged features
The common processFeed resolves effective settings after reading the current saved feed and current Primary rules. Initial generation, manual feed refresh, automatic/scheduled refresh, manual store refresh and retries use that same path. Queue payloads retain IDs/generation numbers; no resolved configuration snapshot is queued. The existing eligibility, transformations, attribute resolution, inventory, XML and GCS generator is reused. Inclusion/exclusion priority and duplicate membership behavior remain in the shared catalog rules. Diagnostics and Single Product Preview remain Primary-only with no new market UI. No Shopify product/metafield mutations were added.

Security and validation
Existing subscribed Shopify authentication and internal backend store authentication scope every read/write. Feed lookups and conditional saves require authenticated store ownership and ADDITIONAL type. Invalid IDs/modes/Country Codes/enums/booleans/arrays and global/unknown JSON fields are rejected. New collection/location IDs are verified against authenticated Shopify nodes; previously valid saved references can be retained/removed as with the existing editor. Edit Market/language are not accepted as mutable fields. Create preserves existing combination, market/language and billing validation. Tests exercise hostile stored JSON, cross-store requests, invalid references, stale revisions, generation races and direct unsupported overrides.

Decisions and limitations
Custom saved values restore on re-enable. Copying is per section, no destructive Copy all action. No persisted drafts. Existing feed identity is immutable except XML ID Country Code. No per-market Diagnostics or preview. Native Polaris wrappers address React 18 custom-element change events and synchronize switch/checkbox properties. Shared package copies are byte-identical and must remain synchronized in future changes. Verification uses mock external services and a local preview, not production feeds or billing. No deployment, migration/backfill, production feed refresh, billing event, or production Shopify mutation was performed.
